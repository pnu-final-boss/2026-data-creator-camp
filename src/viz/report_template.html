GPU 없이 여기까지

이 PC에는 NVIDIA GPU가 없다. librosa·torch 없이 wave+numpy+scipy로 log-mel / MFCC / 자기상관 F0를 직접 구현해, 33.7 GB 원본에서 특징을 한 번만 뽑아 캐시하는 방식으로 전 과정을 CPU에서 끝냈다. 이 숫자들이 앞으로 모든 GPU 실험이 넘어야 할 기준선이다.

M1

신고자 성별 — 사실상 풀렸다

선행연구 대응: griko/voice-gender-classification (임베딩 + 얕은 분류기) 구조를 CPU 특징으로 대체

여성 95.7%, 남성 92.7%로 균형이 좋고 AUC 0.983이다. 남성을 여성으로 오분류한 122건이 가장 큰 오차 덩어리인데, 고음역 남성 화자와 F0 추정의 옥타브 오류가 섞여 있을 것으로 보인다.

가설 검증됨

상위 4개 특징이 전부 F0 계열이었다 — f0_std, logf0_std, logf0_mean, f0_mean. 성별의 1차 단서가 기본주파수라는 선행연구의 전제가 8 kHz 전화망 한국어에서도 그대로 성립한다. 흥미로운 건 평균보다 표준편차가 더 중요했다는 점으로, 억양 변동 폭 자체가 성별 신호를 담고 있음을 시사한다.

모델 비교에서 Logistic Regression(0.9434)이 RandomForest(0.9069)와 HistGradientBoosting(0.9330)을 모두 이겼다. 특징이 이미 잘 설계된 저차원 통계량이라 트리 모델의 비선형성이 이득 없이 분산만 키운 것으로 보인다.

M2

신고자 / 119대원 — 중첩 구간이 천장을 만든다

선행연구 대응: Ozan, arXiv:2106.02422 (콜센터 상담원/고객 구간 분류)

text와 발화 순서를 못 쓰는 조건에서 순수 음향만으로 0.8799를 얻었다. 주목할 건 비대칭 오류다: 119대원을 신고자로 오분류한 경우가 8,573건인 반면 반대 방향은 4,873건으로, 모델이 신고자 쪽으로 치우쳐 예측한다.

예측이 맞았다

사전 조사에서 지적한 37% 중첩 문제가 실제 성능에 그대로 나타났다. 비중첩 구간 0.8944 vs 중첩 구간 0.8550으로 3.9포인트 차이다. 중첩 구간에서 신고자 재현율이 94.4% → 86.7%로 떨어지는데, 상대 발화 위에 얹힌 맞장구가 두 화자의 음향을 섞어버리기 때문이다.

발화 길이별로 보면 0.5–1초 구간에서 0.83, 5초 초과에서 0.97로 단조 증가한다. 짧은 맞장구("예", "네")가 오류의 대부분을 차지한다는 뜻이고, 이는 중첩 문제와 같은 뿌리다 — 맞장구는 짧고 동시에 겹친다.

병목의 정체

오심(nausea)은 신고자가 입으로 말하는 단어가 아니다. 통화에서는 "울렁거려요", "토할 것 같아요"로 나오고, 어노테이터가 이를 임상 용어로 옮긴 것이다. 표층 n-gram으로는 구토와 분리할 근거가 없어, 모델은 구토 정답의 58%, 어지러움의 60%, 복통의 42%에서 오심을 함께 예측한다. macro-F1은 클래스별 단순 평균이므로 이 한 클래스가 전체를 약 0.03 끌어내린다.

바꿔 말하면 M3 개선의 최대 지렛대는 모델 크기가 아니라 오심/구토 쌍의 의미적 분리다. 문맥을 보는 PLM(KLUE-RoBERTa, Kc-ELECTRA)이 여기서 이득을 낼 여지가 가장 크다.

사전 예상이 빗나간 부분

사전 조사에서 "클래스별 임계값 튜닝만으로 macro-F1이 수 포인트 오른다"고 적었으나, 실측은 +0.0001에 그쳤다(0.5847 → 0.5848). class_weight='balanced'가 이미 결정경계를 옮겨놓아 임계값이 할 일이 남지 않았기 때문이다. 두 기법은 더해지지 않고 같은 자리를 다툰다.

다음

여기서 어디로

  • M3에 PLM을 올린다 (우선순위 1). 오심/구토 분리가 최대 지렛대이고, 텍스트 번들이 14 MB라 Colab 전송 비용이 사실상 없다. KLUE-RoBERTa 3 epoch은 T4에서 20~30분.
  • M2는 중첩 구간을 따로 다룬다. 비중첩만으로 학습해 라벨 노이즈를 제거하거나, 중첩 여부를 입력 특징으로 주는 두 갈래를 비교한다. 중첩 판정은 startAt/endAt만으로 계산되므로 추론 시에도 규정상 사용 가능하다.
  • M1은 이미 0.943이라 투자 대비 효과가 가장 낮다. wav2vec2 파인튜닝으로 0.96~0.97까지는 가겠지만, 같은 GPU 시간을 M3에 쓰는 편이 총점에 유리하다.
  • 8 kHz 협대역은 GPU로 옮겨도 그대로 남는 제약이다. wav2vec2/AST는 16 kHz 광대역 사전학습이라 단순 업샘플로는 성능이 깎인다. 먼저 그대로 돌려 기준을 잡고, 필요하면 대역확장을 붙이는 순서가 맞다.

모든 수치는 공식 Validation 3,640통에서 측정했다. M3의 클래스별 임계값은 Training에서 떼어낸 dev 10%(2,920통)에서만 튜닝했고 Validation은 학습·튜닝 어디에도 쓰지 않았다. M1/M2는 Training 29,200통 중 6,000통을 무작위 추출해 학습했으므로(seed 고정), 전량 학습 시 소폭 상승 여지가 있다. macro-F1은 출제 PDF 10쪽의 4단계 절차를 src/common/metrics.py에 그대로 구현해 계산했다.
